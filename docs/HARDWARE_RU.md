# Подключение на основе вашей Bluetooth-прошивки

## 1. Единственный обязательный перенос сигнального провода

На Uno R3 / классическом Nano перенесите **ENA: D1 → D9** при отключённом питании моторов. В исходном `blu_drive.ino` было `ENA = 1`: D1 — TX аппаратного UART, который используется USB-последовательным соединением с Raspberry Pi. D9 поддерживает аппаратный PWM. Распиновка подтверждается [официальной схемой выводов Uno R3](https://docs.arduino.cc/resources/pinouts/A000066-full-pinout.pdf).

| Сигнал вашего проекта | Arduino в новой прошивке | Действие |
|---|---|---|
| L1 | D3 | Сохранить |
| L2 | D2 | Сохранить |
| R1 | D4 | Сохранить |
| R2 | D5 | Сохранить |
| ENA | D9 | Перенести с D1 |
| ENB | D6 | Сохранить |
| TX Bluetooth-модуля | D10 (RX SoftwareSerial) | Сохранить |
| RX Bluetooth-модуля | D11 (TX SoftwareSerial) | Сохранить существующее согласование уровней |
| D14 / A0 | HIGH после старта | Сохранено из исходника; назначение не известно |
| Связь Raspberry Pi ↔ Arduino | USB-порт Arduino | Кабель с передачей данных |

Сопоставление ENA с левой парой, ENB с правой парой — принятое в новом профиле предположение. По старому коду, где оба EN были постоянно HIGH, проверить это нельзя. Проверьте его с поднятыми колёсами. Если стороны перепутаны, в motor.h внутри setElectrical() поменяйте местами только аргументы ENA/ENB у двух вызовов writeWheel(). Пины ENA=D9 и ENB=D6 оставьте; на D1 провод не возвращайте.

Модель драйвера из файлов не определяется. Профиль использует два EN и четыре DIR входа. Если на вашем модуле есть перемычки постоянного включения ENA/ENB, снимите их перед подачей PWM на EN. Не меняйте неизвестные перемычки питания по аналогии с другой моделью драйвера.

Моторы питаются от подходящего источника через драйвер, а не от GPIO/USB Raspberry Pi. Сохраните общую землю Arduino и драйвера. Для Raspberry Pi используйте стабильное питание. USB-связь не требует проводов UART между GPIO Pi и Arduino. Сохраните подходящие уровни сигнала Bluetooth-модуля: наличие стабилизатора питания на модуле не доказывает, что его RX допускает 5 В.

## 2. Что сохранено в командах Bluetooth

Обозначения в таблице относятся к электрическим выходам, а не к гарантированному направлению движения корпуса. `+`: IN1=HIGH, IN2=LOW; `−`: IN1=LOW, IN2=HIGH; `0`: PWM выключен, оба DIR=LOW.

| Команда | Левая сторона | Правая сторона |
|---|---|---|
| F | − | − |
| B | + | + |
| L | − | + |
| R | + | − |
| G | 0 | + |
| I | + | 0 |
| H | + | − |
| J | − | + |
| S или D | 0 | 0 |
| X или x | Без изменения | Без изменения |

В исходнике F вызывала backward(), B — forward(), а H/J — развороты. Новая прошивка сохраняет эти комбинации. Команды `0..9,q` задают примерно 0,10,…90,100% PWM; отсутствующий в исходнике `case '8'` исправлен. Направление и скорость хранятся отдельно: изменение скорости не теряет последнюю команду направления. После S/D команда скорости сама по себе движение не возобновляет.

Начальная скорость Bluetooth — PWM 140 из 255. Команда q по-прежнему разрешает 255. USB/ROS ограничен PWM 140; он не задаёт верхнюю границу для старого Bluetooth-пульта.

## 3. Переключение пультов

Bluetooth работает без Raspberry Pi, если Arduino и драйвер получают питание. При подключённой Pi команда движения Bluetooth немедленно захватывает управление; USB-команды возвращают состояние занятости и не изменяют Bluetooth-движение. Даже постоянные нули Wi-Fi не мешают Bluetooth.

Отпускание кнопки Bluetooth должно отправлять S или D. Это останавливает движение, освобождает Bluetooth и аннулирует старые USB-команды. Через обмен нулями с Pi привод становится доступным Wi-Fi; в браузере нужно снова нажать «Взять управление». Захват/возврат, целиком случившийся между двумя USB-опросами, также регистрируется.

Явный СТОП в браузере отправляет отдельную команду E и останавливает оба источника, если Pi и USB-связь доступны. После E Arduino игнорирует движение Bluetooth до нового S/D: сначала отпустите старую кнопку, затем нажмите её снова. Обычное отпускание Wi-Fi-джойстика, скрытие страницы или потеря Wi-Fi не отправляют глобальный E и не отменяют уже активный Bluetooth.

## 4. Потеря Bluetooth-связи

По умолчанию `BT_COMMAND_TIMEOUT_MS = 0`. Это сохраняет приложение, которое посылает F только при нажатии и S при отпускании. Сам факт «едет, пока держу» не доказывает, что приложение повторяет команды. Таймаут 500 мс без такого повтора останавливал бы робота во время нормального удержания.

В режиме совместимости Arduino не знает о разрыве Bluetooth, если S/D не дошёл. Исходный цикл на micros() также не был надёжным сторожем связи: его время обновлялось независимо от новых Bluetooth-данных.

Доступные варианты:

1. Если приложение повторяет команды движения, например каждые 100 мс, задайте `BT_COMMAND_TIMEOUT_MS = 500` и перепрошейте Arduino. Проверьте остановку после прекращения повторов. Скоростные команды не заменяют повтор движения.
2. Если конкретный модуль имеет надёжный вывод STATE, можно задействовать свободный D8, установив `BT_STATE_PIN = 8`. Прошивка считает HIGH признаком подключения; для иной полярности нужно изменить сравнение в bluetoothLinkReady(). По умолчанию STATE отключён (`-1`). До подключения проверьте документацию именно вашего модуля: мигающий светодиод и устойчивый сигнал «соединение есть» — разные вещи.

Сначала проверяйте движение с поднятыми колёсами. Выключатель питания драйвера должен быть доступен: программный СТОП требует работающего канала и не заменяет отключение питания.

## 5. Загрузка Arduino

1. Откройте `arduino/blu_drive/blu_drive.ino` в Arduino IDE. Файлы `motor.h` и `move_case.h` должны лежать рядом в папке `blu_drive`.
2. Выберите Arduino Uno либо вашу классическую Nano (ATmega328P) и её COM-порт. Для старых Nano клонов выбор загрузчика зависит от установленного bootloader.
3. Скомпилируйте и загрузите прошивку; затем закройте Serial Monitor.
4. Подключите Arduino USB-кабелем к Pi. USB Serial и Bluetooth в этом комплекте работают на 9600 бод.

SoftwareSerial принимает данные с использованием прерываний и задержек внутри обработчика; это видно в [исходном коде Arduino](https://github.com/arduino/ArduinoCore-avr/blob/master/libraries/SoftwareSerial/src/SoftwareSerial.cpp). Скорость USB 9600 выбрана, чтобы уменьшить риск потери UART-байтов при одновременном Bluetooth-приёме. Это не гарантирует безошибочный одновременный обмен на любой плате: проверьте его на своём устройстве. CRC и подтверждения обнаруживают повреждённые пакеты; мост не переоткрывает USB из-за каждой такой ошибки, чтобы не вызывать лишний сброс через DTR.

Первое открытие USB-порта, перезапуск узла с новым открытием или переподключение USB могут сбросить Uno/Nano. До запуска моста остановите Bluetooth-движение. Новая прошивка начинает работу с выключенными PWM.

Для USB/ROS электрические знаки вынесены в `ROS_LEFT_SIGN` / `ROS_RIGHT_SIGN`. Начальные значения −1/−1 соответствуют вашей команде F. Проверьте, что движение ROS вперёд и поворот влево физически верны; исправляйте эти два знака отдельно от таблицы Bluetooth.
