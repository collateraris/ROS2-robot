# Проверки комплекта

Программный прогон 12 октября 2026: **76 Python-тестов — PASS**. Отдельно проходит проверка реального JavaScript интерфейса в Node.js с небольшими заглушками DOM и времени.

Проверены таблица исходных Bluetooth-направлений, PWM и скорость 8/q, приоритет Bluetooth над нулями/ошибками USB, короткое переключение между USB-опросами, общий E и запрет повторного движения до S/D, USB watchdog, CRC/sequence/переполнение и неполная строка. Проверено, что pending E повторяется и не заменяется фоновым нулём; ошибки ACK не переоткрывают USB.

У шлюза проверены вход/Origin, владелец пульта, обычный release и явный global stop, запрет управления в режиме просмотра, camera_required true/false, свежесть ROS/монотонных меток и потеря кадров. JavaScript-проверка выполняет код из настоящего index.html и подтверждает различие автоматического release и нажатия СТОП, режимы камеры и наличие используемых DOM-элементов.

Команды для повторения из корня проекта:

```bash
python3 -m unittest discover -s tests -v
node tests/test_phone_ui.mjs
```

Python-тестам нужны aiohttp и g++; тесту интерфейса — Node.js. Для обычного запуска робота Node.js не нужен: JavaScript работает в браузере телефона.

## Границы проверки

Тесты прошивки компилируют настоящие .ino/.h с g++ и заглушками Arduino/SoftwareSerial; это не сборка настоящим AVR toolchain. Реального ROS-дистрибутива, Arduino, Bluetooth-модуля, камеры и моторного драйвера здесь нет. Проверки узлов используют ROS/serial/camera-заглушки; браузер не испытывался на физическом Android. Тесты не измеряют задержки SoftwareSerial, UART-потери, поведение DTR, ток моторов или остановочный путь.

## Первое испытание на вашем роботе

1. С отключённым питанием моторов перенесите ENA D1→D9, проверьте соответствие EN левой/правой стороне. Поднимите колёса.
2. В Arduino IDE с выбранной настоящей Uno/Nano скомпилируйте и загрузите все три файла новой прошивки.
3. Проверьте старым Bluetooth-приложением F/B/L/R, отпускание S/D и скорость; H/J должны сохранить прежние развороты.
4. Остановите Bluetooth, подключите USB к Pi и запустите новый ROS-пакет. Первое открытие порта может сбросить Arduino; дождитесь готовности.
5. Возьмите Wi-Fi управление, проверьте малую тягу, отпускание джойстика, кнопки СТОП и повторное взятие управления. Положительное ROS linear.x должно физически ехать вперёд, положительное angular.z — поворачивать влево. При необходимости исправьте ROS_LEFT_SIGN/ROS_RIGHT_SIGN.
6. Во время Wi-Fi управления подайте Bluetooth-команду: Bluetooth должен получить управление и не останавливаться от фоновых USB-нулей. После S/D робот должен остаться неподвижным до нового разрешения Wi-Fi.
7. Проверьте явный СТОП браузера при активном Bluetooth: движение должно прекратиться, повтор удерживаемого F не должен возобновлять его до S/D и нового нажатия.
8. Проверьте потерю Wi-Fi с поднятыми колёсами. Для Bluetooth остановка при потере связи по умолчанию не включена; для неё отдельно настройте повтор команд+таймаут или подходящий STATE и испытайте этот режим.

Скорость интерфейса — относительная команда PWM, а не измерение скорости колёс. Начните с небольшого положения ползунка; если моторы не трогаются, это не доказательство отсутствия команд: у драйвера/моторов может быть порог начала вращения.
