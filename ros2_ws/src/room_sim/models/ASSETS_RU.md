# Модели Gazebo Harmonic

Все геометрические модели и текстуры в этой папке созданы для проекта. Загрузки из Fuel, скрытого обращения к сети и внешних mesh-файлов нет. `build_assets.py` воспроизводит текстуры, SDF и URDF средствами стандартной библиотеки Python:

```bash
python3 ros2_ws/src/room_sim/models/build_assets.py
```

Скрипт перезаписывает только папки `models`, `urdf`, `worlds` пакета `room_sim`. При ручном изменении сцены сначала сохрани свою копию мира под другим именем.

## Подключение к запуску

Добавь абсолютный путь к `room_sim/models` в `GZ_SIM_RESOURCE_PATH`. В `worlds/room.sdf` мир называется `room`. Он уже включает ровно одного робота `model://room_robot` с именем `room_robot` и позой `0 0 0.034 0 0 0`. Повторно создавать робота через `ros_gz_sim create` не нужно.

В мире непосредственно описаны стены и мебель; для вариантов сцены можно менять их `<pose>`, добавлять или удалять модели. Вариант мира должен сохранить системные плагины Physics, UserCommands, SceneBroadcaster, Sensors с `ogre2`, Contact, а также include робота. Если запуск использует сервисы `/world/room/...`, имя мира также нужно оставить `room` либо передать соответствующее имя в параметры запуска.

`model://room_environment` служит локальным каталогом текстур. Включать этот ресурсный пустой объект в мир не требуется. `model://human_proxy` — отдельная модель, включённая под именем `person_proxy`.

## Размеры и системы координат

Оси робота: X вперёд, Y влево, Z вверх. Начало `base_link` находится в плоскости осей колёс. В покое эта плоскость примерно на 0.033 м выше пола; начальное размещение на 0.034 м даёт 1 мм зазора до установления контакта.

| Элемент | Размеры / положение относительно `base_link`, м |
|---|---|
| Четыре колеса | Радиус 0.033, ширина 0.025; центры X = ±0.085, Y = ±0.105, Z = 0 |
| Шасси | 0.24 × 0.17 × 0.05, центр `(0, 0, 0.02)` |
| Бампер | 0.27 × 0.25 × 0.025, центр `(0, 0, 0.015)` |
| Габарит в плоскости | X = ±0.135, Y = ±0.125; описанная окружность радиусом 0.184 м |
| `laser` | `(0.035, 0, 0.12)`, без поворота |
| `camera_link` | `(0.12, 0, 0.10)`, без поворота; оптическая ось рендера Gazebo направлена по +X |
| `camera_optical_frame` | То же начало, поворот RPY = `(-π/2, 0, -π/2)` относительно `camera_link`; Z вперёд, X вправо, Y вниз |

В URDF и SDF положения датчиков совпадают. `robot_state_publisher` публикует только постоянные внутренние преобразования. Колёса в URDF закреплены для визуализации: их вращение симулируется отдельно через шарниры SDF. Поток `joint_states` не требуется. URDF не содержит плагина управления и не публикует одометрию.

## Контракт топиков

| Gazebo Transport | Тип | Назначение |
|---|---|---|
| `/sim/cmd_vel` | `gz.msgs.Twist` | Единственный командный вход привода |
| `/scan` | `gz.msgs.LaserScan` | Вход RF2O/SLAM/Nav2; `frame_id = laser` |
| `/camera/image_raw` | `gz.msgs.Image` | RGB, 640 × 480, 15 Гц; `frame_id = camera_optical_frame` |
| `/camera/camera_info` | `gz.msgs.CameraInfo` | Реальная калибровка симулятора; тот же оптический frame |
| `/sim/contacts` | `gz.msgs.Contacts` | Физические контакты бампера (100 Гц) и четырёх колёс (по 20 Гц); world-плагин Contact включён |
| `/sim/odom` | `gz.msgs.Odometry` | Истинная мировая поза, 20 Гц; только оценка результатов |
| `/sim/odom_covariance` | `gz.msgs.OdometryWithCovariance` | Дополнительный вывод истины; по умолчанию не нужен |
| `/sim/ground_truth_tf` | `gz.msgs.Pose_V` | Внутренний вывод истины Gazebo; не мостить в ROS TF |
| `/sim/wheel_odom` | `gz.msgs.Odometry` | Внутренняя интеграция DiffDrive; не мостить и не использовать в навигации |
| `/sim/wheel_tf` | `gz.msgs.Pose_V` | Внутренний вывод DiffDrive; не мостить в ROS TF |

У DiffDrive нет документированного параметра `publish_odom=false` в выбранной версии. `odom_publish_frequency=0` также не означает отключение публикации: исходный код оставляет нулевой период. Поэтому оба его выхода намеренно вынесены в отдельные топики и отдельные frame `sim_wheel_odom`, `sim_wheel_base`. Рабочие `/odom` и `odom → base_link` должны приходить только из RF2O и его guard.

`OdometryPublisher` читает `worldPose(model.Entity())` и непосредственно записывает мировые X/Y и ориентацию в сообщение. Начальная поза не вычитается. Поэтому `/sim/odom` использует абсолютную мировую систему `sim_world`, включая смещение начального размещения. В режиме `dimensions=2` компонент Z не выводится. Модель имеет одинаковое начало с `base_link`.

Лазер: `gpu_lidar`, 720 отсчётов, углы от −π до +π, дальности 0.05–12 м, 10 Гц, гауссов шум σ = 0.01 м. Это приближённая модель C1 для проверки программной цепочки. Она не воспроизводит вращение сканера во времени, зависимость от отражательной способности, пропуски и характеристики реального прибора.

Камера: горизонтальный угол обзора 1.0471975512 рад (60°), разрешение 640 × 480, 15 Гц, ближняя/дальняя плоскости 0.03/12 м. Для проекции используй полученный `CameraInfo`, а не вручную подставленную матрицу K.

Сенсор бампера отслеживает физический бампер, выступающий за колёса в плане. Кроме него, на каждом из четырёх колёс установлен отдельный сенсор контактов: он ссылается на collision только своего link и публикует в общий `/sim/contacts`. Контакты колёс с полом обеспечивают наблюдаемый поток реальных данных и при поездке без препятствий. Дополнительных искусственных heartbeat-сообщений нет.

Harmonic Contact публикует только непустые контакты; отсутствие столкновений бампера само по себе не создаёт сообщений. Поэтому при проверке исправности потока учитываются и настоящие контакты колёс с полом, а при подсчёте столкновений с препятствиями оценщик исключает пол и собственные части робота. Если робот висит в воздухе без контактов, поток может отсутствовать — номинальная частота сенсоров не гарантирует постоянной публикации. Неинструментированные части корпуса и контакты между двумя редкими выборками всё ещё могут ограничивать полноту метрики.

## Комната и человек

Внутренний размер комнаты 8 × 6 м. Есть стол на четырёх ножках, стул, диван, шкаф, коробка и цилиндрический макет растения. Текстуры дерева, пола, ткани и штукатурки процедурные и воспроизводимые. Никакие реальные фотографии или сторонние лицензируемые наборы не включены.

`person_proxy` — статический набор цилиндров, бокса и сферы высотой примерно 1.66 м. Его можно переставлять сервисом изменения позы Gazebo. Он нужен для геометрии, сопоставления камеры со сканом и проверки интерфейсов. **Успешное или неуспешное обнаружение этого макета не измеряет качество детектора людей.** Для оценки восприятия нужны реалистичные независимые сцены, реальные записи и размеченная выборка. В комплекте нет анимации походки, трекинга или фотометрически корректной модели человека.

## Проверенные первичные источники

Параметры сверены с документацией Gazebo Sim 8 (Harmonic) и исходным кодом веток `gz-sim8`, `gz-sensors8`, `sdf14`:

- [DiffDrive API](https://gazebosim.org/api/sim/8/classgz_1_1sim_1_1systems_1_1DiffDrive.html): повторяемые `left_joint` и `right_joint`, `odom_topic`, `tf_topic`, `frame_id`, `child_frame_id`.
- [DiffDrive.cc](https://github.com/gazebosim/gz-sim/blob/gz-sim8/src/systems/diff_drive/DiffDrive.cc): параметр частоты и отдельные паблишеры интегрированной одометрии.
- [OdometryPublisher API](https://gazebosim.org/api/sim/8/classgz_1_1sim_1_1systems_1_1OdometryPublisher.html) и [исходный код](https://github.com/gazebosim/gz-sim/blob/gz-sim8/src/systems/odometry_publisher/OdometryPublisher.cc): `odom_frame`, `robot_base_frame`, `dimensions`, чтение мировой позы.
- [Harmonic migration guide](https://gazebosim.org/docs/harmonic/migrating_gazebo_classic_ros2_packages/): native `gpu_lidar`, `gz_frame_id`, мост `ros_gz`.
- [CameraSensor.cc](https://github.com/gazebosim/gz-sensors/blob/gz-sensors8/src/CameraSensor.cc) и [camera.sdf](https://github.com/gazebosim/sdformat/blob/sdf14/sdf/1.9/camera.sdf): `optical_frame_id` и `camera_info_topic`; оптический frame используется и в изображении, и в калибровке.
- [Contact example](https://github.com/gazebosim/gz-sim/blob/gz-sim8/examples/worlds/contact_sensor.sdf) и [Contact.cc](https://github.com/gazebosim/gz-sim/blob/gz-sim8/src/systems/contact/Contact.cc): системный плагин Contact, вложенный в `contact` топик, поиск collision внутри родительского link и публикация только при наличии контактов.

Проверка XML и согласованности ресурсов не является запуском Gazebo или подтверждением физической точности модели.
