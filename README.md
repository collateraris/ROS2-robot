# Робот: управление с телефона по Wi-Fi через ROS 2

Комплект исходного кода для ручного управления четырёхколёсным роботом с передней камерой. Телефон открывает пульт в браузере; Raspberry Pi принимает команды, публикует их в ROS 2, передаёт PWM на Arduino и отправляет изображение на телефон.

**Основная конфигурация:** Raspberry Pi 4/5 + Ubuntu Server 24.04 arm64 + ROS 2 Jazzy; USB UVC-камера; Arduino Uno R3 / классический Nano ATmega328P; два канала драйвера для левой и правой сторон. Поворот — разностью скоростей сторон. Шасси с рулевой сервой требует другой прошивки и преобразования команд.

Это исходный комплект для сборки и стендовой проверки, не испытанная на вашем железе система. Настоящий запуск ROS 2 на Pi, нативная AVR-сборка и испытание двигателей здесь не выполнялись. Результаты проверок описаны в `docs/TESTING_RU.md`.

## Что скачать и читать

Полный архив содержит папку `robot_wifi_teleop`. После распаковки именно в ней должны находиться `arduino`, `docs`, `ros2_ws`, `scripts`, `tests`.

1. `docs/HARDWARE_RU.md` — совместимость, подключение, питание, пины и прошивка.
2. `docs/INSTALL_RU.md` — установка Ubuntu/ROS 2 на Pi, ROS 2 в Windows 11 через WSL2, сборка и запуск.
3. `docs/ARCHITECTURE_RU.md` — ROS-топики, браузерный API, протокол Arduino и остановка.
4. `docs/TESTING_RU.md` — выполненные проверки и последовательность первого испытания.

## Где выполняется код

| Компонент | Файл / каталог | Назначение |
|---|---|---|
| Arduino | `arduino/robot_drive/robot_drive.ino` | Направление, PWM, watchdog, подтверждение команд |
| Raspberry Pi: камера | `robot_web_teleop/camera_node.py` | UVC → BGR8 и JPEG в ROS 2 |
| Raspberry Pi: моторы | `robot_web_teleop/motor_bridge.py` | Свежий `TwistStamped` → serial + контроль ACK |
| Raspberry Pi: шлюз | `robot_web_teleop/web_node.py` | ROS-подписки и публикация команд пульта |
| Raspberry Pi: HTTP/WS | `robot_web_teleop/web_server.py` | Вход, JPEG, WebSocket, один владелец управления |
| Общая логика | `robot_web_teleop/control.py`, `protocol.py` | Проверка возраста команд, смешивание, CRC |
| Телефон | `web/index.html` | Изображение, джойстик, остановка; HTML/CSS/JS без сборки |
| Запуск | `launch/robot.launch.py`, `config/robot.yaml` | Три узла, параметры, общее завершение при выходе узла |

Python-каталог, `web`, `launch` и `config` находятся внутри `ros2_ws/src/robot_web_teleop/`.

Телефону нужны браузер и доступ к той же локальной сети. APK, Play Store, приложение ROS и компьютер в цепочке управления не требуются. Веб-страницу нужно открывать **с Raspberry Pi**, а не как локальный HTML-файл. Windows используется для установки, прошивки Arduino и разработки. После запуска в `tmux` компьютер можно отключить, если Wi-Fi обеспечивает отдельный роутер.

## Короткий запуск после установки ОС и прошивки

На Raspberry Pi из распакованной папки:

```bash
cd ~/robot_wifi_teleop
bash scripts/install_jazzy.sh pi
```

Выйти из сеанса и войти снова, чтобы применились группы `dialout` и `video`. Затем:

```bash
source /opt/ros/jazzy/setup.bash
cd ~/robot_wifi_teleop/ros2_ws
rosdep install --from-paths src --ignore-src -y --rosdistro jazzy
colcon build --symlink-install
tmux new -s robot
```

Внутри `tmux`:

```bash
cd ~/robot_wifi_teleop
bash scripts/run_robot.sh serial_port:=/dev/ttyACM0 camera_device:=/dev/video0
```

Имена устройств — примеры. Перед запуском определить фактические через `ls -l /dev/serial/by-id/` и `v4l2-ctl --list-devices`. Сценарий спросит пароль пульта длиной минимум 8 символов, пароль не записывается в исходники.

На телефоне открыть `http://IP_RASPBERRY_PI:8080`, войти, дождаться изображения и готовности Arduino, нажать **«Взять управление»**, удерживать джойстик. Отпустить — нулевая команда. **СТОП** выключает управление; для продолжения нужно включить его снова.

Чтобы отсоединиться от терминала, нажать **Ctrl+B**, отпустить, затем **D**. Для возвращения: `tmux attach -t robot`; для завершения узлов — **Ctrl+C** внутри сеанса. После перезагрузки Pi запустить проект снова; автозапуска этот комплект не создаёт.

## Начальные параметры

| Параметр | Начальное значение | Смысл |
|---|---|---|
| Камера | 640×480, 15 кадров/с, JPEG quality 70 | Запрашиваемый режим, фактический зависит от камеры |
| Видеопульт | Последовательные JPEG-запросы, примерно до 10 кадров/с | Последний кадр без накопления очереди |
| HTTP / WebSocket | 8080 | Пульт, видео и команды на одном адресе |
| Пространство имён | `/robot` | Позволяет переименовать набор ROS-топиков |
| `ROS_DOMAIN_ID` | 42 | Одинаковый для узлов и диагностического терминала Pi |
| Обнаружение ROS | `LOCALHOST` | В базовой схеме ROS-процессы общаются внутри Pi |
| USB serial | 115200, 8N1 | Должно совпадать с прошивкой |
| Ширина колеи | 0.18 м | Заменить на расстояние между левой и правой сторонами |
| Предел PWM | 140 из 255 | Программный предел также встроен в Arduino |
| Максимум команды | 0.25 м/с, 1.8 рад/с | Номинальная шкала, без измерения скорости |

Уменьшайте скорость для первого теста, но учитывайте трение: при начальном положении ползунка 35% прямая команда в этой конфигурации даёт примерно 31 PWM. Если моторы не стартуют, проверьте проводку и питание, затем на поднятых колёсах кратковременно увеличьте ползунок. Не держите неподвижный мотор долго под током.

## Принцип остановки

Пульт требует явного включения и удержания джойстика. Уход со страницы, потеря связи, устаревшее видео, отсутствие свежих команд или готовности Arduino выключают управление. После восстановления соединения автоматически ехать он не начнёт.

На Raspberry Pi проверяются возраст команды и соответствующий ACK Arduino. На Arduino есть независимый watchdog 350 мс: отсутствие валидной команды обнуляет PWM и блокирует движение до нулевой команды. Точные условия и ограничения — в `docs/ARCHITECTURE_RU.md`.

Камера показывает оператору передний обзор. Автоматического распознавания препятствий, карты, одометрии и удержания точной скорости в комплекте нет. При движении назад ориентируйтесь непосредственно по роботу; задней камеры здесь нет. Нулевой PWM не гарантирует мгновенную остановку колёс. Первый тест проводят с поднятыми колёсами и доступным физическим выключателем моторного питания.

Пульт рассчитан на свою локальную Wi-Fi-сеть. HTTP не шифрует пароль и команды; пароль страницы ограничивает случайное управление, но не превращает локальный канал в защищённый интернет-сервис. Не публикуйте порт 8080 через роутер. Для локальных поездок внешний интернет после установки не нужен.

## Несколько роботов

У каждого Pi свой IP, порт по умолчанию 8080 и собственный пароль. Можно открывать несколько вкладок по адресам разных роботов. Указать имя второго робота при запуске:

```bash
bash scripts/run_robot.sh namespace:=robot2 serial_port:=/dev/ttyACM0 camera_device:=/dev/video0
```

Это отдельные пульты, без диспетчера флота и согласования траекторий. Одним роботом в каждый момент управляет только одна WebSocket-сессия; другие вошедшие пользователи могут смотреть и нажать СТОП.
